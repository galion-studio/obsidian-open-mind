# D-414 — console.galion.studio / dashboard.galion.studio: retire or add? (slot 414, 2026-10-28 20:22 CET +01:00)

Evidence: docs/ops/console-studio-tls-diag.md. Both names are NXDOMAIN, not in
the tunnel, never served. Nothing is broken; this is a tidy-up decision.

## D-414-1 — what to do with the two names

* **A. Retire (recommended).** Keep DNS as is (no records). In code, a later
  slot removes them from console-ui `CONSOLE_HOSTS`, the fleet/SERVICES data
  (`hosts: ["console.galion.app"]`) and the test fixture; mark the Caddy
  compose template as legacy. Zero DNS/tunnel change, zero risk, one less
  public admin entry point. Note `is_console_host` still accepts any
  `console.*` / `dashboard.*` host, so nothing breaks if a name is added later.
* **B. Add as aliases.** Owner adds two proxied CNAMEs to the tunnel and two
  ingress rules `-> http://127.0.0.1:8080` (same as console.galion.app), then
  `cloudflared` restart. Cost: a DNS change + a live tunnel restart (owner
  window), and a second public door to the admin console (more attack
  surface, cookie domain split between .app and .studio so admin sign-in would
  not carry over). Only worth it if the .studio brand needs its own console URL.
* **C. Redirect only.** Add the names but answer with a 301 to
  console.galion.app (Cloudflare redirect rule). Same DNS change as B, no
  second admin door. Middle ground if old links exist (none were found in 7
  days of cloudflared logs).

Recommendation: **A**. No traffic in 7 days, never resolved, and B/C each need
a DNS change plus tunnel work for no current user.

## D-414-2 — re-word F-396-4

Change F-396-4 to "not in DNS (NXDOMAIN), not in tunnel; exit 35 is the box
proxy" so nobody chases an edge-TLS ghost. Recommend yes (doc-only).
