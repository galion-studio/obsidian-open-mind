## 2. What this branch changes (`.cargo/config.toml` only)

1. `[env] CFLAGS = "-fno-asynchronous-unwind-tables -fno-unwind-tables"` — C (only the
   bundled SQLite today) is built without unwind tables. cc-rs keeps its defaults
   (`-Oz`, section flags, `-fPIC`). Safe: release is `panic = "abort"`, and rusqlite never
   lets a Rust panic unwind through a C frame (callbacks are wrapped in `catch_unwind`).
   Not a CPU/SIMD flag. Any `CFLAGS`/`CFLAGS_<triple>` env var still replaces it.
2. `LIBSQLITE3_FLAGS` += `-DSQLITE_DEFAULT_MEMSTATUS=0 -DSQLITE_OMIT_DECLTYPE
   -DSQLITE_OMIT_DEPRECATED -DSQLITE_OMIT_PROGRESS_CALLBACK -DSQLITE_OMIT_SHARED_CACHE`
   (from https://sqlite.org/compile.html#recommended_compile_time_options). No crate uses
   any of them (grep), and a future use fails at link time, not at run time.
   Rejected because they change behaviour: `DQS=0`, `MAX_EXPR_DEPTH=0`,
   `DEFAULT_WAL_SYNCHRONOUS=1`, `OMIT_AUTOINIT`, `USE_ALLOCA`.
3. A comment warning not to build releases with `CFLAGS=-O2` + `CRATE_CC_NO_DEFAULTS=1`.
4. New gated real test `crates/hermes-gateway/tests/real_size_trim.rs` (`GALION_REAL=1`).

No new dependencies and no code changes. Second commit (restart r1, 20:4x CET): `crates/hermes-gateway/Cargo.toml` `default = ["sqlite"]`, `coding` opt-in (option 4a, section 6).
