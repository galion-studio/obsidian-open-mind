# Publish blocker B8: Cloudflare 403 challenge from the VPS IP (evidence only)

Probe time: 2026-10-27 17:46 CET (+01:00). Read-only HTTPS GET/HEAD only. **No Cloudflare, DNS, tunnel or WAF change was made.** VPS IP masked as `51.38.x.x`.

## Evidence
| Host | From box (non-VPS egress) | From VPS (`51.38.x.x`) |
|---|---|---|
| console.galion.app | 302 (server: cloudflare) | **403**, `cf-mitigated: challenge` |
| one.galion.app | 200 | **403**, `cf-mitigated: challenge` |
| api.galion.app | 502 (origin/route issue, separate) | **403**, `cf-mitigated: challenge` |

Origin on the VPS loopback: `curl http://127.0.0.1:8080/` → 302 (console after the 17:29 CET cutover, same as external from the box). So the origin is healthy; the 403 is a Cloudflare managed challenge that applies to the VPS's own egress IP (datacenter/OVH ASN reputation, Bot Fight Mode, or a security-level/WAF rule). Real users from residential IPs are not affected, as the box probe shows.

Impact: only self-probes and health checks from the VPS through the public hostname. Any VPS-side monitor must use loopback, or one of the options below.

Side finding: `api.galion.app` returns 502 from outside. That is a separate origin/route issue and not part of B8.

## Options for the owner (Slavik), pick one. None has been applied.
1. **Do nothing (recommended for launch):** VPS health checks use loopback (`127.0.0.1:8080`) and external checks run from the box or a third-party monitor. Zero CF change.
2. **WAF custom rule "Skip" for the VPS IP** (`ip.src eq <VPS IP>`, skipping managed challenge, Bot Fight/Super Bot, and security level). Narrowest allowlist.
3. **IP Access Rule "Allow"** for the VPS IP on the zone. Simpler but broader (it bypasses all WAF for that IP).
4. **Turn off Bot Fight Mode, or lower the Security Level**, zone-wide. Not recommended because it weakens protection for everyone.
5. **Probe through the tunnel/origin hostname with a secret header and a matching skip rule.** More setup; a header secret would need to be handled in secrets (not documented here).

If you choose 2 or 3, the owner applies it in the CF dashboard. Re-verify with `curl -sI https://console.galion.app/` from the VPS and expect no `cf-mitigated` header.
