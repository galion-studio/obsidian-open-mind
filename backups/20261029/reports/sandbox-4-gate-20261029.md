## 3. Proposed enforcement design (NOT applied)

Pipeline: **Hermes proposes → CI `sandbox` check → sandbox deploy (isolated platform copy) → security checks → signed pass record → human approval → gated live apply by the deploy tool.** The spend guard sits across every stage.

Steps in order:
1. **Spend guard first ($5).** Set the Hermes daily and session caps so the total is ≤ $5 (replace `70-research-budget.conf`: daily USD 5 or less, session lower). Set `HANDOFF_BUDGET_USD` ≤ the remainder, and point the box `hermes-research` LIMIT at the same $5 ledger. When the limit is reached, a single **pause file** (for example `/var/lib/hermes-rs/PAUSE`) makes Hermes, the handoff and the sandbox runner all refuse new work. No sandbox or deploy stage runs while it is paused.
2. **Model-tier routing.** Change `model.default` from opus to the cheap tier (`galion`=haiku or `river-flash`). Use `worker`=sonnet for routine coding. Keep `boss`=opus only for deep reasoning (gate reviews, threat analysis, owner-escalation). Log each call's tier in the pass record so spend per gate is visible.
3. **Unprivileged Hermes.** Create system users `hermes-rs` and `hermes-desk` (nologin). In the units: `User=`, `CapabilityBoundingSet=` (empty), `ProtectHome=yes`, `InaccessiblePaths=/opt/galion/galion-light/secrets /root`, `IPAddressDeny=any` plus allow loopback and the LLM endpoints (or an egress proxy), `SystemCallFilter=@system-service`, `RestrictAddressFamilies=AF_INET AF_INET6 AF_UNIX`. Change `.env` to `root:hermes-rs 640`, or use `LoadCredential=` instead. Apply the same hardening to `galion-desk`.
4. **Hermes holds no push or deploy credentials.** Hermes never sees `github.token`, the gh login or SSH keys. Its output is a patch or bundle written to a spool directory (`/var/lib/hermes-rs/outbox/`), and nothing else.
5. **Sandbox deploy stage (the live-style copy).** Add a dedicated, unprivileged `galion-sandbox` user and a throwaway root such as `/var/tmp/sandbox-deploy-<ts>` (per the sandbox_vps_only rule). It runs the candidate binaries on spare ports with copied, non-secret config and fake keys, under openmind-sandbox plus systemd `--user` / cgroup limits, with no access to `/opt/galion` or live ports. Better still is a separate VM/LXC on the PVE host, which also gets Landlock (fixes B8).
6. **Security checks in the sandbox run.** fmt, clippy -D warnings, tests including the ignored real sandbox suites (`GALION_REAL=1 … -- --ignored`, `real_sh_sandbox`, hermes-tools `sandboxed` with CI unset, failing on any skip), cargo-deny licences, gitleaks, no-python, a diff-scope check (no changes to secrets, units or deploy paths unless declared), health probes of the deployed copy, and an egress/escape test.
7. **Signed pass record.** The runner writes `PASS.json` (git SHA, binary sha256, check results, skip count = 0, spend, model tiers, Zagreb timestamp) and signs it with **minisign** using a key that only the `galion-sandbox` runner holds (not Hermes, not box agents).
8. **CI required check `sandbox`.** Add a `sandbox` job (self-hosted runner on the sandbox VM, or `workflow_dispatch` that verifies the uploaded signed PASS for the head SHA). Make it a required status check on `main` alongside self-eval fmt/clippy/test/gitleaks/no-python. Branch protection: PR required, 1 approving review (the owner), no force-push, no deletion, include administrators, CODEOWNERS on `deploy/`, `.github/` and `crates/galion-deploy/`.
9. **Gated deploy script.** Change `galion-deploy` to refuse unless (a) `PASS.json` verifies against the pinned minisign public key, (b) the binary sha256 matches the record, (c) the record's SHA is an ancestor of protected `main`, (d) an owner approval file exists, signed by the owner's own key, or the approval is a GitHub Environment approval for that SHA, and (e) the spend guard is not paused. Drop-ins are installed only from the reviewed repo `deploy/` tree, through the same tool.
10. **Close the hand-deploy path.** Remove `grokbot-box` (and other agent keys) from root's authorized_keys. Give agents an unprivileged `swarm` SSH user, read-only for probes, with a forced-command wrapper for `push-branch` that requires a PASS record for the branch head. Root login is for the owner only.
11. **Push helper.** `push-branch.sh` checks for a signed PASS for `git rev-parse <branch>` before it uploads the bundle, and runs as the `swarm` user using a fine-grained token with `contents:write` limited to `swarm/*`. The ruleset blocks that token from `main`.
12. **Audit.** Every stage appends a line to an append-only ledger (nerve event + file): who, SHA, PASS id, approval id, spend.
