## Stop it coming back: console-dist install step

There is no console-dist install step in the repo; the live tree was unpacked
on 2026-09-22 / 2026-10-18 without a umask, which produced 666/777. New
subcommand (std only) in `galion-deploy`:

```
galion-deploy dist-install SRC DEST    # copy, dirs 755 / files 644 / exec 755, swap in, keep DEST.old-<stamp>
galion-deploy dist-check DIR           # list group/other-writable or set-id entries (exit 1 if any)
galion-deploy dist-rollback DEST OLD   # put OLD back (DEST -> DEST.failed-<stamp>)
```

* Never copies a source mode; drops set-uid/set-gid/sticky; refuses absolute or
  escaping symlinks and special files; builds `DEST.new-<pid>` next to DEST,
  runs `dist-check` on it, then two renames. A failed copy leaves DEST untouched.
* `ProtectSystem=strict` + `ReadOnlyPaths=/opt/galion/console-dist` on both
  console units do not create a separate mount for console-dist
  (`/proc/<pid>/mountinfo` has no console-dist entry), so a host-side rename is
  visible to the running service; the static index of the serving binary may
  still need a restart to pick up *new* file names (separate decision).
* Recommended future install: `galion-deploy dist-install /var/tmp/console-dist-<ver> /opt/galion/console-dist`, then `galion-deploy dist-check /opt/galion/console-dist`.
