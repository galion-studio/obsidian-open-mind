What it shows:
- **ONE-PROBE**: `/api/v1/awake` and `/api/v1/analytics/services` report
  `one` up on port 19050 and `voice` on 19051. Nothing listens on 8091/8002 on
  the box, so `one: ok:true` can only come from dialling its own bind.
- **/api/v1/services**: same JSON as live; the ports follow `GALION_MIND` /
  `GALION_MEMORY`; memory is up through the stand-in.
- **Pairing fails closed**: no cookie gives 401 everywhere; a wrong code gives
  `no`; the right code (lower-case, uppercased before hashing) sets the
  cookie; 5 wrong codes lock it (`later`, even for the right code); with the
  store removed the old cookie is refused (`you:false`, 401).
- **Pure-Rust SQLite**: `defence` comes from the guardian fixture and
  `memory.counts` from the WAL fixture (600/333/1, as in the `.expected` files).

## 5. Comparison

Status code and content type match live for every unpaired route (diff of
`method path status content-type`: no differences). Byte sizes differ only
where the body is fixture data (pages, catalog) or carries live values
(`/link` ports, `/api/v1/awake` numbers, `/api/v1/services` ports). Paired
routes were not compared (no live cookie, on purpose). Cutover notes:
[../one-probe-cutover.md](../one-probe-cutover.md).
