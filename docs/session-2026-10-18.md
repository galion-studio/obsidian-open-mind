Details: `~/workflows/vps/hermes-openrouter-proposal.md`.

### 6.1 Findings
- **Bug 1, OpenRouter key not visible to Hermes:**
  - Hermes runs with `gateway.multiplex_profiles: true`. In that mode it reads profile secrets only from `/opt/galion/hermes/.env` and does not fall back to the process environment.
  - `OPENROUTER_API_KEY` exists only in `/root/galion-secrets/hermes.env`.
  - Result: `RuntimeError: No LLM provider configured`, logged on 2026-10-17 at 21:27 CEST (+02:00).
- **Bug 2, the `galion` model 404 storm:**
  - Galion One sends the bare model id `galion`, which Hermes forwards to River.
  - The logs hold 1,169 × `Model 'galion' not found` (3,601 × HTTP 404 in total). The `keep_warm()` loop repeats it every 240 s.
  - Study B counted 734 such errors on 2026-10-18 alone.
- **Bug 3, a cost risk once Bug 1 is fixed.** When River returns 429, background tasks (title generation, compression) fall back to the **paid** `~anthropic/claude-opus-latest`. This only failed so far because of Bug 1.
- **memory-gateway shares the same OpenRouter key** and runs its fallback model as primary.

  2. Port the 2 Python helpers (`desk-hermes.py` and link-watch, about 320 lines) to Rust.
  3. A systemd unit for Galion One.

  5. GPU only as Provider rows; keep heavy runtimes off the VPS.
